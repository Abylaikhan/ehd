description: Разбить план на упорядоченный, трассируемый список задач (tasks.md)
argument-hint: <NNN или slug фичи>
---

Сгенерируй `specs/$ARGUMENTS/tasks.md` по шаблону `.specify/templates/tasks-template.md`.

1. Прочитай `spec.md`, `plan.md`, `data-model.md`, `contracts/`.
2. Разбей на атомарные задачи в порядке исполнения (TDD: тест раньше реализации). Для каждой задачи:
   - ID (`T001`…), краткое действие.
   - Трассировка к требованию (`REP-FR/BR` и раздел спеки).
   - **Затронутые файлы** — получи через `graphify_impact` (не угадывай пути).
   - Тип: test | impl | migration | wiring | docs. Пометь `[P]` независимые (параллелизуемые) задачи.
   - Критерий готовности (наблюдаемый результат / команда проверки).
3. Порядок по умолчанию: контракты/тесты → domain → repository (GORM) → application → transport → wiring в `internal/app` → интеграционные тесты → docs/OpenAPI.
4. Обязательно включи негативные security-тесты (скрытая колонка, запрещённый оператор, оба режима RLS) как отдельные задачи — до задач, расширяющих функциональность.

Не выдумывай пути файлов и имена символов — только из Graphify/плана.
