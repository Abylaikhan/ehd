Ты пишешь **спецификацию** (не реализацию) для бэкенда ЕХД.

Фича: $ARGUMENTS

Обязательный порядок:

1. **Изучи контекст только через инструменты** (Grep/Glob запрещены):
   - `graphify_freshness`; при устаревании — `graphify_build update=true`.
   - `graphify_locate` / `graphify_query` — найди существующий связанный код и его контракты.
   - Найди применимые требования в `../.tz_extracted.txt` (ID `REP-FR-###` / `REP-BR-###`).
2. Определи следующий номер `NNN` (просмотри `specs/` через Read) и создай `specs/NNN-<slug>/spec.md` по шаблону `.specify/templates/spec-template.md`.
3. Заполни: цель и ценность, пользовательские сценарии, функциональные требования (со ссылками на `REP-FR/BR`), контракты API (эндпоинт, коды ошибок из ТЗ), сущности данных, нефункциональные ограничения, критерии приёмки.
4. **Запрещено** в спеке: детали реализации (имена функций/пакетов, SQL, выбор библиотек). Только «что» и «зачем».
5. Отметь неоднозначности маркером `[NEEDS CLARIFICATION: …]` — их разрешит `/clarify`.

Спека обязана соответствовать `.specify/memory/constitution.md`. Каждое утверждение о существующем коде подтверждай Graphify/Read — ничего не выдумывай.
