Реализуй `specs/$ARGUMENTS/` строго по `tasks.md`.

Предусловие: `/analyze` без blocker'ов. Иначе останови и сообщи.

Для каждой задачи по порядку:

1. Перечитай задачу и её трассировку. Уточни затронутые файлы через `graphify_impact` (не Grep/Glob).
2. TDD: сначала тест (падающий), затем минимальная реализация до зелёного.
3. Пиши код в стиле окружения (Fiber/GORM/zap/viper; домен чист; репозиторий — GORM-модели). Никаких `SELECT *`, обхода RBAC/RLS, секретов в логах.
4. Проверка после задачи: `go build ./...`, `go vet ./...`, `gofmt -l .` (пусто), релевантные `go test`.
5. Отметь задачу выполненной ТОЛЬКО при наблюдаемом зелёном результате. Упало — сообщи с выводом, не помечай.

После всех задач:
- Интеграционная проверка на запущенном стеке (`docker compose -f docker-compose.dev.yml`), `/readyz` зелёный, реальный сценарий из критериев приёмки.
- `graphify_build update=true` — обнови граф.
- Обнови OpenAPI (`openapi/`) и README при изменении контракта.
- Сверься с Definition of Done в конституции.

Каждое утверждение о результате подтверждай выводом инструмента. Ничего не выдумывай.
