# Спецификация: Модуль ОБМ ЕВГА — подключение к БД и реестр рисков 5-15а (read-only)

- **ID**: 007-evga-registry
- **Статус**: implemented (backend)
- **Требования ТЗ**: EVGA-FR-010…019, EVGA-BR-010/011 (частично), OQ-11 (решение «по ИИН»)
  — источник `../tz/obm-evga-5-15a/` (02-reestr-riskov.md, 03-statusy.md, 12-otkrytye-voprosy.md, 14-shema-bd.md)
- **Дата**: 2026-09-06

## 1. Цель и ценность

Аудитор ДВГА и куратор КВГА получают в ЕХД реестр записей витрины рисков `its_tb_5_15a`
внешней БД `obm_evga` (прод, 6,5 млн строк): просмотр, фильтрация, карточка записи,
выгрузка в Excel. Первый этап модуля — строго **только чтение** внешней БД; никакой записи
в `obm_evga` не выполняется.

## 2. Пользовательские сценарии

- Как **аудитор ДВГА** я открываю реестр и вижу только записи своего департамента,
  чтобы работать по своей зоне ответственности (EVGA-FR-010).
- Как **куратор КВГА** я вижу записи всех департаментов в режиме чтения и могу
  отфильтровать по департаменту (EVGA-FR-011).
- Как аудитор я фильтрую реестр (профиль, статус, период, ГУ, ИИН, сумма, вхождение
  в уведомление, № уведомления) и листаю страницы (EVGA-FR-013).
- Как аудитор я открываю карточку записи с полным составом полей отработки.
- Как аудитор я выгружаю отфильтрованный реестр в Excel (EVGA-FR-017).
- Ошибочные потоки: пользователь без роли модуля → 403; аудитор, чей ИИН не найден
  в `obm_evga.users` или без департамента → пустой реестр + явный признак причины;
  внешняя БД недоступна → 503 с кодом `EVGA_SOURCE_UNAVAILABLE`.

## 3. Функциональные требования

| ID | Требование (поведение) | Источник ТЗ |

| FR-2 | Все соединения с `obm_evga` открываются в режиме **read-only** (`default_transaction_read_only=on` на уровне сессии); модуль не выполняет INSERT/UPDATE/DELETE/DDL | Указание владельца 06.09.2026 |

## 4. Контракты API

Все маршруты — `/api/v1/evga`, доступ: активная сессия + роль `evga_auditor` | `evga_curator` | админ.
Ошибки — единый контракт `{request_id, error:{code,message,details}}`.

| Метод | Путь | Право | Описание |
|---|---|---|---|
| GET | `/registry` | роли модуля | Реестр: query-параметры фильтров/пагинации (FR-6/7); ответ `{items:[…], total, page, page_size, scope:{department_id, department_title, all_departments:bool, unmapped:bool}}` |
| GET | `/registry/:id` | роли модуля | Карточка записи (в пределах видимости); 404 `NOT_FOUND` вне видимости |
| GET | `/registry/export` | роли модуля | XLSX той же выборки; `Content-Disposition: attachment` |
| GET | `/references` | роли модуля | `{statuses:[{id,title,code}], profiles:[{id,title}], departments:[{id,title}]}` (departments — только куратору/админу) |

Коды ошибок: `UNAUTHENTICATED` (401), `ACCESS_DENIED` (403, нет роли модуля),
`INVALID_FILTER` (400, неизвестное поле сортировки/некорректные параметры),
`NOT_FOUND` (404), `EVGA_SOURCE_UNAVAILABLE` (503, внешняя БД недоступна).
`unmapped:true` в `scope` — ИИН не сопоставлен/нет департамента: `items=[]`, `total=0`, 200 OK.

## 5. Сущности данных

- **RiskRecord** — строка витрины: идентификатор, платёж (`ppo_pp`, дата, сумма `amount_part`),
  отправитель (`gu`, `gu_bin`, `sendername`), получатель (`iin`, `fm/nm/ft`, `la1`),
  классификация (профиль, департамент, период `god`/`mes`), отработка (статус, комментарий,
  `refund`, `amount_for_vozvrat`, мероприятие), связи (№ уведомления, № исходящего).
- **DepartmentScope** — результат резолва пользователя: `department_id`+`title` | все департаменты | не сопоставлен.
- **Reference** — элемент справочника (`id`, `title`, `code`).

## 6. Нефункциональные ограничения

- Витрина 6,5 млн строк / 9 ГБ: только серверная пагинация; `COUNT` по той же выборке;
  p95 списка ≤ 3 с на проде (замер в конце фазы 1 на VPN).
- Внешняя БД — отдельный пул (max 5 conn), таймаут запроса 30 с через context.
- ИИН пользователя не логируется (ни в открытом, ни в расшифрованном виде); в логах — `user_id`.
- Пароль внешней БД — только env, не попадает в логи/ответы.
- Сортировка/фильтры — только whitelist-поля, значения — типизированные параметры (Принцип 3).

## 7. Критерии приёмки

1. Given пользователь с ролью `evga_auditor` и ИИН, существующим в `obm_evga.users` с департаментом X,
   When GET `/registry`, Then все строки имеют департамент X и `scope.department_id = X` (FR-3/4; AT-01 ТЗ).
2. Given пользователь с ролью `evga_curator`, When GET `/registry` без `department_id`,
   Then строки разных департаментов; When с `department_id=X` — только X (FR-4).
3. Given аудитор, чей ИИН отсутствует в `obm_evga.users`, When GET `/registry`,
   Then 200, `items=[]`, `scope.unmapped=true` (FR-3).
4. Given пользователь без ролей модуля, When GET `/registry`, Then 403 `ACCESS_DENIED`.
5. Given фильтр `in_notice=true`, Then у всех строк заполнен № уведомления; `=false` — у всех null (FR-6).
6. Given `sort=unknown_field`, Then 400 `INVALID_FILTER` (негативный тест, FR-7).
7. Given запись с `in$trash=1` в витрине, Then она не видна ни в списке, ни в карточке (FR-8).
8. Given GET `/registry/export` с фильтрами, Then XLSX с теми же строками и колонками грида (FR-11).
9. Given `EVGA_PG_DSN` не задан, Then `/api/v1/evga/*` → 404, `/readyz` без ключа `evga` (FR-1).
10. Соединение с внешней БД: `SHOW transaction_read_only` = `on` (FR-2, интеграционная проверка).

## 8. Вне объёма

Изменение статусов, массовые операции, журнал статусов (фаза 3); формирование уведомлений (фаза 4);
PDF (фаза 5); маршрут/согласование/нумерация (фаза 6); ЕСЭДО (фаза 7; **запросы в ЕСЭДО запрещены**);
любые записи в `obm_evga`; миграции §14 ТЗ; фронтенд-слой (отдельная спека фронт-харнесса).
