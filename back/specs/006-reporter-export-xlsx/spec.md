# Спецификация: Reporter — Export XLSX

- **ID**: 006-reporter-export-xlsx
- **Статус**: implemented
- **Требования ТЗ**: REP-BR-008, REP-BR-009; раздел «Экспорт в Excel»; раздел 10 (`POST /reporter/views/{slug}/export`)
- **Дата**: 2026-08-24

## 1. Цель и ценность
Завершает пользовательскую вертикаль данных: выгрузка всего отфильтрованного набора опубликованного представления в XLSX. Экспорт использует **тот же QuerySpec и валидатор**, что и `/query` (slice 005) — повторно проверяет роль, RLS и фильтры, выбирает только `exportable=true` колонки, применяет row scope и потоково отдаёт бинарный XLSX. Файл нигде не сохраняется.

## 2. Пользовательские сценарии
- Пользователь с ролью нажимает «Экспорт» → backend повторно проверяет роль и опубликованную конфигурацию → формирует XLSX по текущим фильтрам (не текущую страницу) → отдаёт `attachment` XLSX-стрим.
- Заголовки Excel — `label` колонок, не `source_name`; попадают только `exportable=true` колонки.
- Обычный пользователь получает только строки своего row scope (тот же RLS, что и в таблице).
- Если набор превышает лимит (100 000) — экспорт отклоняется с понятным кодом.
- Если экспорт уже выполняется в системе — параллельный запрос отклоняется `EXPORT_BUSY`.

## 4. Контракты API
- `POST /reporter/views/{slug}/export` — тело `QuerySpec` (filters/search; page/cursor игнорируются) → бинарный XLSX-стрим (`200`), либо ошибка (`401/403/404/413/429/503`).

## 5. Сущности данных
Новых таблиц нет. Лимит берётся из `published_snapshot.export_row_limit` (≤ 100 000). Порядок строк — по keyset-ключу представления (детерминированный).

## 6. Нефункциональные ограничения
- excelize `StreamWriter` (низкая память при формировании). Значения ячеек приводятся к простым типам; NULL → пусто.
- Только read-only SELECT; идентификаторы из whitelist, значения — параметры (наследуется от querybuilder slice 005).
- Одновременность экспорта — process-глобальный семафор (cap 1).
- Форматирование значений (даты/деньги/проценты по `format`) и маскирование — базовое; расширенное форматирование позже.

## 7. Критерии приёмки
- **AC-1**: `POST /export` для пользователя с ролью → `200`, `Content-Type` XLSX, `Content-Disposition: attachment`, `Cache-Control: no-store`; тело — валидный XLSX.
- **AC-2**: заголовки листа = `label` видимых `exportable` колонок; неэкспортируемые/скрытые отсутствуют.
- **AC-3**: число строк данных = число строк того же `/query` с теми же фильтрами (с учётом RLS).
- **AC-4**: пользователь без роли → 403; без сессии → 401; неопубликованное/disabled → 404.
- **AC-5**: RLS применён — обычный пользователь выгружает только свой row scope.
- **AC-6**: при наборе > `export_row_limit` → отказ `EXPORT_TOO_LARGE` (413); проверка без полного COUNT.
- **AC-7**: во время активного экспорта параллельный → `EXPORT_BUSY` (429).

## 8. Вне объёма
- Аудит-модуль (запись факта экспорта) — отдельный слайс.
- Расширенное форматирование ячеек (числовые/денежные/датовые форматы, mask_rule) — позже.
- Асинхронный/фоновый экспорт больших наборов; постраничный стрим прямо из курсора БД (сейчас материализация до `export_row_limit`).
- Пользовательская сортировка по произвольной колонке (порядок по keyset-ключу).
