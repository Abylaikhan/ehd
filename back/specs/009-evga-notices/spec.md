# Спецификация: ОБМ ЕВГА — формирование уведомлений (проекты)

- **ID**: 009-evga-notices
- **Статус**: implemented (backend)
- **Требования ТЗ**: EVGA-FR-016, EVGA-FR-030…039, §8.4, §11.4 (удаление проекта),
  ответы аналитика 07.09.2026 (А1 — повторные нельзя; В4 — «Отозван» освобождает записи;
  Б4 — адресат вручную; Б5 — записи без ГУ только ошибкой)
- **Дата**: 2026-09-07

## 1. Цель

Аудитор отмечает записи реестра и формирует по ним проекты уведомлений: система группирует
записи по ГУ, аудитор выбирает адресата каждой группе, создаются шапка, снимок строк
и адресат. Номер НЕ присваивается (это момент отправки на согласование — фаза 6);
статусы записей витрины НЕ меняются (меняются при регистрации исходящего — фаза 7).

## 3. Критерии приёмки

1. AT-07: записи 3 разных ГУ → 3 уведомления, у каждого свой адресат (проверка на реплике).
2. Запись в статусе ≠ 1 → в `rejected` с причиной; запись уже в действующем уведомлении → причина с номером; после отзыва того уведомления (stat 15) запись снова доступна.
3. Запись с пустым `gu` → `rejected: gu_empty`.
4. Группа без `its_cli_id` → 400, ни одно уведомление группы не создано.
5. Повторный `POST /notices` с теми же записями → все в `rejected` (уже в действующем уведомлении) — гонка закрыта `FOR UPDATE`.
6. `DELETE` проекта → уведомление и строки исчезают из списков, записи витрины снова доступны для формирования; `DELETE` не-проекта → 422.
7. Снимок содержит `gu`/`gu_bin`; поле `tb_5_15a` = NULL.
8. При `EVGA_WRITE_ENABLED=false` — preview/список/карточка работают, create/delete → 403.

## 4. Вне объёма

Номер уведомления и отправка на согласование (фаза 6), PDF (фаза 5), маршрут, статус 4
и каскад по платежу (фаза 7, EVGA-FR-067а), редактирование состава строк существующего
проекта (добавим при фазе 6 вместе с ограничениями §11.4), UI (фронт-спека 007-evga-notices-ui).

## Clarifications

- ⚠ Платформенные поля `its_req.entity_id/entity_pk/entity_uuid`, `company_id`, `project_id`:
  в сэмплах заявок уведомлений нет, `entities` в реплику не снята. Заполняем best-effort:
  `entity_pk` = id уведомления, `entity_uuid` = его `sys$uuid`, остальное NULL.
  Снять фактический образец с прода при следующем VPN-подключении и выровнять.
- Статусы записей витрины при создании проекта НЕ меняются (ТЗ: статус 4 — только при
  регистрации исходящего).
