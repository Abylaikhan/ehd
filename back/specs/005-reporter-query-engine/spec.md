# Спецификация: Reporter — Query Engine (безопасное чтение данных)

- **ID**: 005-reporter-query-engine
- **Статус**: implemented
- **Требования ТЗ**: REP-FR-040, REP-FR-050..055; раздел «Правила безопасного SQL builder»; раздел «Ограничение строк»; раздел «Поиск, фильтрация, сортировка и пагинация»; REP-BR-003..007; Принципы конституции 3 и 4
- **Дата**: 2026-08-24

## 1. Цель и ценность
Третий кирпич вертикали: по опубликованному представлению (slice 004) выполнить **безопасный read-only SELECT** к ClickHouse и вернуть данные конечному пользователю. Это первый реальный вывод строк. Движок применяет whitelist колонок, типизированные параметры, серверную таблицу совместимости операторов, RBAC по ролям и **row-level security по профилю пользователя**. Даёт метаданные для рендера таблицы, страницу данных (keyset) и точный `total_count`.

## 2. Пользовательские сценарии
- Пользователь открывает опубликованное представление по `slug`; получает метаданные (колонки, типы, разрешённые операторы, параметры пагинации).
- Пользователь запрашивает данные с фильтрами/поиском/сортировкой → страница строк только из видимых колонок, с применённым RLS; отдельно — точный `total_count`.
- Пользователь без подходящей роли → 403; представление отключено/не опубликовано → 404.
- Обычный пользователь с профилем (регионы/подразделения) видит только разрешённые строки; строки с NULL в колонке ограничения не возвращаются.
- Пользователь с полностью пустым профилем — полный доступ к строкам (согласованный fail-open, отдельный security-тест).
- Администратор делает предпросмотр черновика (первые N строк) тем же движком до публикации.

## 4. Контракты API (раздел 10)
Пользователь (сессия):
- `GET  /reporter/views` — список доступных пользователю опубликованных представлений (по ролям).
- `GET  /reporter/views/{slug}` — метаданные: колонки (label, display_type, операторы, флаги), параметры пагинации, имя.
- `POST /reporter/views/{slug}/query` — тело `QuerySpec` → `{columns, rows, page:{next_cursor, page_size}}`.
- `POST /reporter/views/{slug}/count` — тело `QuerySpec` (фильтры/поиск) → `{total_count}`.

Администратор:
- `POST /reporter/admin/views/{id}/preview` — тело `QuerySpec` → предпросмотр строк текущей конфигурации черновика (без RLS).

**QuerySpec** (единственный принимаемый контракт):
```
{ "filters":[{"column","operator","value"|"values"}], "search":"", "sort":{"dir":"asc|desc"},
  "page_size":50, "cursor":"<opaque>" }
```
Дополнения к расширению Data View (нужны для движка): у представления добавляются `keyset_column` (стабильный ключ, по умолчанию — первичный ключ таблицы), `row_scope_region_column`, `row_scope_department_column` (физические колонки для RLS). Включаются в snapshot.

## 5. Сущности данных
Расширение `data_views`: `keyset_column`, `keyset_dir`, `row_scope_region_column`, `row_scope_department_column` (все — опциональные строки). Отражаются в `published_snapshot`. Новых таблиц нет.

## 6. Нефункциональные ограничения (Принцип 3)
- Идентификаторы (колонки, ключ) — из whitelist, экранируются backtick + проверяются регулярным выражением `^[A-Za-z_][A-Za-z0-9_]*$`; `database`/`table` — через `{name:Identifier}`.
- Значения — только named-параметры ClickHouse (`{q:String}`, `{regions:Array(String)}`, `{cursor:UInt64}` …). Никакой конкатенации пользовательского ввода.
- Запросы: LIMIT всегда; `max_execution_time`, `max_result_rows`, `max_memory_usage`, `query_id`.
- Только read-only SELECT. Никаких JOIN/UNION/подзапросов/функций от клиента (QuerySpec, не SQL).
- Аудит/логи — без чувствительных значений фильтров.

## 7. Критерии приёмки
- **AC-1**: `GET /views/{slug}` для опубликованного → метаданные с видимыми колонками и разрешёнными операторами; для disabled/не опубликованного → 404.
- **AC-2**: `POST /query` без сессии → 401; с ролью не из snapshot → 403.
- **AC-3**: фильтр по колонке вне whitelist или не `filterable` → 422; недопустимый оператор для типа → 422.
- **AC-4**: попытка инъекции в значение фильтра/поиск → безопасно (значение как параметр, строк-инъекции нет); в имя колонки — отклонено валидацией.
- **AC-5**: ответ содержит только видимые колонки; скрытая (`department_code`) отсутствует в rows и в тексте SQL (проверка по логам/EXPLAIN).
- **AC-6**: keyset-пагинация: первая страница + `next_cursor`; вторая страница продолжает без пропусков/повторов; `page_size` вне 20–200 нормализуется.
- **AC-7**: RLS by_profile — пользователь с регионами видит только свои строки; строки с NULL в колонке ограничения не возвращаются; `total_count` согласован с RLS.
- **AC-8**: fail-open — пользователь с пустым профилем в режиме by_profile получает все строки (security-тест).
- **AC-9**: админ-предпросмотр — строки без применения RLS.
- **AC-10**: `total_count` точный и учитывает фильтры+RLS.
