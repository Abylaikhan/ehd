# Спецификация: Auth Module

- **ID**: 001-auth-module
- **Статус**: implemented
- **Требования ТЗ**: REP-FR-001, REP-FR-002; раздел «Регистрация, ЭЦП и сессии»; раздел 9 (модель данных auth); раздел 10 (REST API /auth)
- **Дата**: 2026-08-21

## 1. Цель и ценность
Auth Module — внутренний модуль ЕХД: регистрация, аутентификация (логин/пароль и ЭЦП через NCALayer), сессии, пользователи, роли и профиль доступа (регионы/подразделения). Даёт другим модулям доверенную личность пользователя через внутренний интерфейс (без сети) для RBAC/RLS.

## 2. Пользовательские сценарии
- Гость регистрируется по логину/паролю → статус `pending`, витрины недоступны до активации админом.
- Пользователь входит по логину/паролю → получает сессию (max 3 часа).
- Пользователь с временным паролем обязан сменить его при первом входе.
- Администратор проверяет ИИН, назначает роли, регионы и подразделения, разблокирует после 3 неудачных входов.
- Другой модуль (Reporter) получает `Identity` по активной сессии.

## 4. Контракты API (раздел 10)
Публичные: `POST /auth/register`, `POST /auth/login`, `POST /auth/eds/challenge`, `POST /auth/eds/verify`.
Пользователь: `POST /auth/change-password`, `GET /auth/me`, `POST /auth/logout`.
Администратор: `GET /auth/admin/users`, `PATCH /auth/admin/users/{id}`, `POST /auth/admin/users/{id}/unlock`, `POST /auth/admin/users/{id}/temp-password`, `GET/POST /auth/admin/roles`, `GET /auth/admin/regions`, `GET /auth/admin/departments`.
Все ответы содержат `request_id`; ошибки — единый контракт `{request_id, error:{code,message,details}}`.

## 5. Сущности данных (раздел 9)
users, roles, user_roles, sessions, regions, departments, user_regions, user_departments. Персональные поля зашифрованы; ИИН имеет HMAC.

## 6. Нефункциональные ограничения
- Пароли — стойкий хеш (bcrypt); ИИН/ФИО/телефон — AES-GCM; ключ вне БД (env). Секреты не в логах.
- Cookie сессии — HttpOnly, SameSite, Secure (в non-local). Проверка прав — на backend.
- Metadata API p95 ≤ 500 мс.

## 7. Критерии приёмки
- AC-1: register → пользователь `pending`, повторный тот же ИИН → 409.
- AC-2: login верный → сессия+cookie; неверный ×3 → блокировка; unlock админом → снова вход.
- AC-3: временный пароль → `password_change_required=true`; change-password по политике снимает флаг.
- AC-4: `/auth/me` без сессии → 401; с сессией → Identity с ролями и кодами региона/подразделения.
- AC-5: admin PATCH назначает роль/регион/подразделение; не-админ на /auth/admin/* → 403.
- AC-6: ИИН/ФИО/телефон в БД зашифрованы (не читаемы как текст); в логах их нет.

## 8. Вне объёма
- Реальная валидация ЭЦП-сертификата/цепочки/отзыва через NCALayer (интерфейс `Verifier` + sandbox-заглушка; реальная интеграция — Phase 2).
- Rate limiting, CSRF-токен-эндпоинт, email-подтверждение.
