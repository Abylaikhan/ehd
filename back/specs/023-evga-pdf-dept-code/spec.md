# Спека 023 — код ДВГА в бланке уведомления: убрать подстановку кода региона

Статус: принята (13.10.2026). Исправляет дефект, внесённый при доработке шаблона PDF.
Связанные: 005-evga-pdf, 022-evga-names-order-sender.

## Дефект

Запрос данных PDF брал код ДВГА как `coalesce(nullif(trim(d.code),''), reg.region_code, '')`.
У департаментов без собственного кода подставлялся **код региона**, и в подвале
официального документа печаталось «ДВГА по Жетісу КВГА МФ РК (код 19)», где 19 —
код региона, а не код ДВГА. В утверждённом образце
`tz/obm-evga-5-15a/Уведомление_об_устранении_нарушения.pdf` кода ДВГА нет вообще.

## Факты из боевой БД (13.10.2026)

Скрипт `tz/obm-evga-5-15a/scripts/checks_prod_dictionaries.sql`, запрос «ВОПРОС 5».

| Показатель | Значение |
|---|---|
| Департаментов (живых) | 22 |
| С заполненным `its_departments.code` | **18** |
| С заполненным `its_departments.bin` | 0 |
| Формат кода | 5-значный бюджетный код: `30301`, `35801`, `32101` … |
| Без кода | 4: Абайская, **Жетісу**, Павлодарская, Улытау |

То есть код ДВГА в данных существует и это НЕ код региона.

## FR-1. Источник кода ДВГА

- Код ДВГА = **только** `its_departments.code`. Откат на `its_regions.region_code` отменён.
- Код пуст → в подвале печатается одно наименование департамента, без скобок
  (поведение `deptLine` не меняется).
- Нумерация уведомлений `region_code` по-прежнему использует (EVGA-FR-070) — это другой
  реквизит, он не затронут.

## Ограничение

Место размещения кода в бланке **не согласовано**: в утверждённом образце его нет,
а замечание аналитика «отсутствует код ДВГА» места не указывает. До ответа код
остаётся в подвале рядом с наименованием департамента (вопрос 3 документа №7).

## Приёмка

- AT-1: у департамента с кодом (напр. Туркестанская, `35801`) в подвале печатается его код.
- AT-2: у ДВГА по Жетісу код не печатается — вместо прежнего ошибочного «(код 19)».
- AT-3: номер уведомления по-прежнему формируется с кодом региона.
