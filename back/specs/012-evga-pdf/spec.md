# Спецификация: ОБМ ЕВГА — PDF уведомления по утверждённому образцу

- **ID**: 012-evga-pdf
- **Статус**: implemented
- **Требования ТЗ**: EVGA-FR-040…049 (§9); образец —
  `../tz/obm-evga-5-15a/Уведомление_об_устранении_нарушения.pdf` (получен 09.09.2026)
- **Дата**: 2026-09-09

## 1. Разбор образца (источник истины по вёрстке)

Альбомный A4, весь текст тёмно-синий. Структура (§9.1 подтверждена):
1) казахское уведомление; 2) казахское приложение; 3) русское уведомление; 4) русское приложение.
- **Шапка** (на титульной странице каждой языковой части): слева «Қазақстан Республикасы
  Қаржы министрлігі Ішкі мемлекеттік аудит комитеті» (жирный), в центре эмблема КВГА,
  справа «Министерство финансов Республики Казахстан Комитет внутреннего государственного
  аудита» (жирный). **Водяной знак** — та же эмблема, крупно, полупрозрачно, на каждой странице.
- **Адресат** справа: рус — наименование + код ЕСЭДО («…» - 2294440); каз — только наименование.
- **Текст** — утверждённый §9.2 (рус) и казахская версия из образца, ключевые обороты жирным.
- **Приложение**: заголовок справа («Приложение к уведомлению №<номер> Комитета…» /
  «…№<номер> хабарламасына қосымша»), таблица: № п/п | Код ГУ отправителя | Номер платежа |
  Дата платежа (ДД.ММ.ГГГГ) | Фамилия | Имя | Отчество | ИИН | Карт-счет | Сумма (два знака).
  Профиль риска НЕ выводится (EVGA-FR-046).
- **Подвал** (курсив, после таблицы): «ДВГА по <область> КВГА МФ РК, / Подписано:
  <должность> <ФИО подписанта> / Исп. <ФИО>, тел <т>, эл.адрес <e> / Уведомление №:<н> от <д>»
  (каз: «Қол койған: …», «Орын. …», «Хабарлама №:<н> <д> жіберілді»).

## 2. Решения (ADR)

- **Библиотека**: `github.com/go-pdf/fpdf` (поддерживаемый форк gofpdf; UTF-8 TTF).
  Новая зависимость — вне утверждённого стека, фиксируется здесь как ADR.
- **Шрифты**: DejaVu Sans (Regular/Bold/Oblique), вшиты `go:embed` — полное покрытие
  казахской кириллицы (ә, ғ, қ, ң, ө, ұ, ү, і). Лицензия приложена.
- **Эмблема и водяной знак**: извлечены из утверждённого образца (PNG с прозрачностью), `go:embed`.
- **Хранение**: PDF генерируется **на лету** (`GET /notices/:id/pdf`). Запись в `files`(S3)
  платформы отложена — у нас нет доступа к их S3; снимок строк неизменен → документ
  детерминирован (выполняет требование неизменности §9.4.3 по данным). Вопрос S3 — к Бауыржану.
- Данные подвала: подписант = `signer_id → users` (должность `hr_position.title`);
  до подписания — надпись «(до подписания состав подвала предварительный)» не выводим,
  просто текущий назначенный последний согласующий не подставляется: если `signer_id` пуст,
  строка «Подписано:» содержит прочерк (проект PDF, §9.4.1/2).
- Дата уведомления: `its_out.doc_date` (после регистрации) → иначе `signer_date` → иначе
  текущая дата (проект).

## 3. Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | `GET /api/v1/evga/notices/:id/pdf` — роли модуля, в пределах видимости; ответ `application/pdf`, `Content-Disposition: attachment; filename="uvedomlenie-<номер|id>.pdf"` |
| FR-2 | Состав и порядок секций/колонок/форматов — строго по образцу (см. §1); четыре секции, водяной знак на каждой странице, шапка на титуле каждой языковой части |
| FR-3 | Данные: адресат из `its_risk_notice_recepient → its_cli` (title, title_kk, code); номер `its_req.docnum` (пусто → «б/н», проект); строки — снимок `its_risk_notice_5_15a` в порядке `id`; департамент, подписант+должность, исполнитель (`created_by → users`: short_name, office_tel_number, email) |
| FR-4 | Форматы: дата ДД.ММ.ГГГГ; сумма с двумя знаками (как в образце, без разделителей разрядов) |
| FR-5 | Кнопка «Скачать PDF» в карточке уведомления (UI) |
| FR-6 | Юниты: генерация валидного PDF (магическая сигнатура, >4 страниц на образцовых данных), форматирование сумм/дат |

## 4. Приёмка (AT-16/17)

1. PDF по уведомлению с ≥12 строками: 4 секции в правильном порядке, таблица разбивается
   по страницам, колонки соответствуют образцу (визуальная сверка).
2. Казахские символы отображаются корректно (ә/ғ/қ/ң/ө/ұ/ү).
3. AT-17: после изменения витрины (пересчёт) содержимое PDF не меняется — данные из снимка.
4. Подписанное уведомление показывает фактического подписанта (AT-13-связка).

## 5. Вне объёма

Запись файла в `files`/S3 платформы (нет доступа — вопрос Бауыржану), вложение PDF
в исходящее ЕСЭДО (после ШЭП), редактирование текста администратором (текст утверждён
образцом; редактор — при необходимости позже).
