# Спека 024 — изменение состава адресатов на доработке

Статус: принята (13.10.2026, ответ аналитика).
Закрывает: вопрос 2 документа `voprosy-analitiku-7-itogovyy.md` (п.2 замечаний, доп.).
Связанные: 009-evga-notices, 010-evga-approval, 018-evga-notice-attrs, 022 FR-2.

## Основание

Ответ аналитика 13.10.2026:

> «Менять адресатов можно на этапе доработки, если при отправке на согласование оно было
> отправлено назад на доработку, то тогда можно.»

До этого адресаты задавались один раз при формировании и не менялись никогда.

## FR-1. Когда изменение разрешено

Состав и порядок адресатов изменяются **только** когда уведомление находится в статусе
«Отправлен на доработку» (`its_req.stat_id = 12`, `domain.ReqStatRework`).

В любом другом статусе запрос отклоняется с `ErrNoticeNotEditable`:

| Статус уведомления | Изменение адресатов |
|---|---|
| 1 «Проект создан» | **нет** — проект удаляется и формируется заново (FR-9 спеки 009) |
| 2 «На согласовании» | нет |
| 5 «На подписании» | нет |
| **12 «Отправлен на доработку»** | **да** |
| 3 «Отправлен объекту аудита» | нет |
| 15 «Отозван» | нет |

## FR-2. Контракт

`PUT /api/v1/evga/notices/:id/recipients`, тело `{"its_cli_ids": [12, 7, 33]}`.

- Массив **упорядочен**: позиция определяет `its_risk_notice_recepient.nn = 1..N`
  (как при формировании, спека 022 FR-2).
- Пустой массив отклоняется: уведомление без адресата недопустимо.
- Повтор одного и того же адресата отклоняется.
- Замена полная: прежние строки адресатов гасятся `in$trash = 1`, новые вставляются.
  История не теряется — строки остаются в таблице.
- Права: как у прочих изменений — аудитор своего департамента либо админ,
  при включённом режиме записи (`EVGA_WRITE_ENABLED`). Видимость департамента проверяется.

## FR-3. Интерфейс

В карточке уведомления в статусе «Отправлен на доработку» блок адресатов становится
редактируемым: добавление из справочника ЕСЭДО, удаление, изменение порядка стрелками.
В остальных статусах — только просмотр, как раньше.

## Ограничение

Изменение адресатов не отражается в журнале: отдельной таблицы истории адресатов
в `obm_evga` нет, а колонок `created_at`/`updated_at` в `its_risk_notice_recepient`
тоже нет (проверено на боевой БД 13.10.2026). Прослеживаемость обеспечивается только
погашенными строками `in$trash = 1`.

## Приёмка

- AT-1: в статусе 12 замена адресатов проходит, `nn` соответствует переданному порядку.
- AT-2: в статусе 1, 2, 5, 3 запрос отклоняется с 409/ErrNoticeNotEditable.
- AT-3: пустой список и дубликат адресата отклоняются с 400.
- AT-4: прежние адресаты остаются в таблице с `in$trash = 1`, в карточке не показываются.
- AT-5: аудитор другого департамента получает 404/403 — чужое уведомление не меняется.
