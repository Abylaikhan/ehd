# Спека 016 — назначение пользователя в департамент ДВГА из админки (ОБМ ЕВГА)

Статус: принята (запрос пользователя).
Связанные: 007-evga-registry (видимость по департаменту, FR-3/4).

## Проблема

Видимость аудитора определяется связкой «ИИН пользователя ЕХД → `obm_evga.users.its_departments_id`».
Если в `obm_evga` нет записи с таким ИИН, пользователь получает `unmapped`: пустой реестр и отказ
при формировании уведомлений. Сейчас привязка делается только вручную SQL-вставкой в внешнюю БД.

Писать привязку в `obm_evga` нельзя: в боевой среде эта БД **read-only** (ТЗ, спека 007 FR-2),
поэтому админка не может опираться на запись во внешнюю систему.

## Решение

Привязка хранится в БД ЕХД как **переопределение** (override) и имеет приоритет над резолвом по ИИН.

### FR-1. Хранение
Таблица `evga_user_departments` в БД ЕХД: `user_id` (PK, пользователь ЕХД) → `department_id`
(идентификатор департамента из `obm_evga.its_departments`). AutoMigrate, как у маршрута (спека 010 ADR).

### FR-2. Резолв видимости
`Service.Scope` при расчёте области:
1. админ/куратор → все департаменты (без изменений);
2. **иначе сначала** проверяется override из `evga_user_departments`; если задан — область = этот департамент
   (название берётся из справочника `its_departments`);
3. если override нет — прежний резолв по ИИН (`DepartmentByUserIIN`);
4. если и его нет — `unmapped` (пустой реестр, не ошибка).

### FR-3. Управление (только администратор)
- `GET /api/v1/evga/admin/users/:uid/department` — текущая привязка пользователя.
- `PUT /api/v1/evga/admin/users/:uid/department` — `{department_id: <id>|null}`; `null` снимает
  переопределение (возврат к резолву по ИИН).
Не админ → 403 `ACCESS_DENIED`. Неизвестный департамент → 422 `INVALID_FILTER`.

### FR-4. Инвалидация кэша
Область видимости кэшируется 15 минут (спека 007 FR-3). При изменении привязки кэш
соответствующего пользователя сбрасывается — изменение действует сразу, без перезахода.

### FR-5. UI
В карточке пользователя админки (экран «Пользователи») — поле **«Департамент ДВГА (ОБМ ЕВГА)»**:
выпадающий список департаментов (из `/evga/references`, доступен админу), с возможностью очистить.
Сохраняется вместе с карточкой.

## Ограничения

- Переопределение не изменяет данные `obm_evga` — внешняя БД остаётся read-only.
- Список департаментов читается из `obm_evga.its_departments` (SELECT, допустимо).

## Приёмка

- AT-1: админ назначает департамент пользователю без записи в `obm_evga` → у того появляется реестр этого департамента.
- AT-2: изменение действует сразу (без ожидания 15 минут и перезахода).
- AT-3: снятие привязки (`null`) → возврат к резолву по ИИН; если его нет — `unmapped`.
- AT-4: не админ получает 403 на оба эндпоинта.
- AT-5: override имеет приоритет над ИИН-резолвом.
