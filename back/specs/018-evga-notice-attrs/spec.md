# Спека 018 — реквизиты формы уведомления (ОБМ ЕВГА)

Статус: принята (замечания по тестовой системе, п.3).
Связанные: 009-evga-notices (формирование), 011-evga-outgoing (исходящее).

## Проблема

В новой форме уведомления отсутствуют реквизиты действующей формы: «Инициатор»,
«Дата создания», «Комментарий», «Номер документа», привязка «Исходящего письма»,
«Порядок» для адресата. Несколько адресатов уже реализованы ранее.

## Поведение

### FR-1. Реквизиты в карточке `GET /notices/:id`
Ответ дополняется:
- `initiator` — ФИО создателя уведомления (`its_risk_notice.created_by` → `users.short_name`);
- `created_at` — дата создания (уже есть в шапке);
- `docnum` — номер документа (уже есть в шапке);
- `out_doc_num`, `out_doc_date` — реквизиты привязанного исходящего письма (`its_out`);
- `recipients[]` — адресаты с порядком: `{nn, cli_id, title}`, сортировка по `nn`;
- `comment` — произвольный комментарий к уведомлению.

### FR-2. Комментарий
Колонки для комментария в `its_risk_notice` нет, а внешняя БД в боевой среде read-only,
поэтому комментарий хранится в БД ЕХД (таблица `evga_notice_meta`, ключ — id уведомления).
`PUT /notices/:id/comment` с телом `{comment}`; доступ — как у прочих изменений
(аудитор/админ, режим записи включён). Куратор — только чтение.

### FR-3. UI
Во вкладке «Документ» карточки уведомления выводятся: Номер документа, Дата создания,
Инициатор, Исходящее письмо (№ и дата), список адресатов с порядковыми номерами,
редактируемое поле «Комментарий» с сохранением.

## Приёмка

- AT-1: в карточке видны инициатор, дата создания, номер документа.
- AT-2: при созданном исходящем показаны его № и дата; до создания — прочерк.
- AT-3: адресаты выводятся по порядку `nn` (1, 2, …).
- AT-4: комментарий сохраняется и отображается после перезагрузки карточки.
- AT-5: куратор комментарий изменить не может (403).
