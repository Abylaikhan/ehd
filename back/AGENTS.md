# ЕХД Backend (`ehd-api`) — операционные правила агента

Ты работаешь над **бэкендом** ЕХД: Go 1.26, модульный монолит (Auth + Reporter в одном процессе), архитектура по go-clean-template. Это отдельный harness со своим Knowledge Graph. Режим работы — **Spec-Driven Development (SDD)**.

Эти правила ОБЯЗАТЕЛЬНЫ и имеют приоритет над привычками по умолчанию.

---

## 1. MCP-first. Grep/Glob для анализа структуры ЗАПРЕЩЕНЫ

Понимание кода строится **только через инструменты**, а не через догадки. Маршрутизация:

| Задача | ЕДИНСТВЕННО правильный инструмент | Запрещено |
|---|---|---|
| «Где определён X / где используется Y» | `mcp__graphify` → `graphify_locate`, `graphify_query` | Grep, Glob, `find` |
| «Как устроен модуль / что с чем связано» | `graphify_overview`, `graphify_subgraph`, `graphify_explain`, `graphify_path` | чтение вслепую |
| «Что сломает моё изменение» | `graphify_impact` | догадки |
| Навигация по Go-символам, find usages, тип, рефактор | `mcp__jetbrains` (GoLand MCP) | ручной парсинг |
| История, blame, diff, изменённые файлы | `mcp__git` | `Bash(git ...)` наугад |
| Состояние контейнеров, логи, compose | `mcp__docker` | лишние `docker` вызовы |
| Прочитать конкретный известный файл | `Read` | — |

- Grep и Glob перехватываются hook-ом и **блокируются**. Не пытайся обойти их через `Bash(grep …)` / `Bash(find …)` — это то же нарушение.
- Перед структурными выводами вызови `graphify_freshness`. Если граф пуст/устарел — `graphify_build` (`update=true`). После своих изменений в коде — снова `graphify_build update=true`.
- GoLand MCP требует запущенного GoLand с открытым проектом `back/`. Если он недоступен — используй Graphify + `Read`, но НЕ Grep/Glob.

## 2. Анти-галлюцинации (жёстко)

- **Ни одного утверждения о коде без подтверждения инструментом.** Путь к файлу, имя функции/типа/поля, сигнатура, ключ конфига, имя таблицы/колонки, эндпоинт — сначала подтверди через Graphify/Read/GoLand, потом пиши.
- Не выдумывай API библиотек (Fiber, GORM, zap, viper, clickhouse-go). Не уверен в сигнатуре — открой исходник зависимости через `Read`/GoLand или проверь в go.mod версию и документацию.
- Если инструмент вернул ошибку или пусто — так и скажи и повтори запрос иначе. **Никогда не выдавай предполагаемый результат за фактический.**
- Не «додумывай» требования ТЗ. Источник требований — `../.tz_extracted.txt` и `../TZ_Reporter_ClickHouse.docx`; ссылайся на ID (`REP-FR-###`, `REP-BR-###`).
- Числа, лимиты, коды ошибок бери из ТЗ/конституции, не из памяти.

## 3. SDD-гейт: код только после спецификации

Порядок неизменен: `/specify` → `/clarify` → `/plan` → `/tasks` → `/analyze` → `/implement`.

- Нельзя писать/менять код продакшн-логики без принятого `specs/NNN-*/spec.md`, `plan.md` и `tasks.md`.
- Каждая задача в `tasks.md` трассируется к требованию ТЗ (`REP-FR/BR`) и к затронутым файлам (список получен через `graphify_impact`).
- Спека описывает ПОВЕДЕНИЕ и КОНТРАКТ, не реализацию. План и задачи — реализацию.
- Любое изменение должно соответствовать `.specify/memory/constitution.md`. Конфликт со конституцией → останавливайся и фиксируй в `/analyze`, не «прогибай» правило молча.

## 4. Проверка перед «готово»

- Компиляция: `go build ./...`. Статика: `go vet ./...`, `gofmt -l .` (пусто).
- Тесты: `go test ./...`. Для query builder / authz / RLS — обязательны негативные тесты (запрещённая колонка, оператор, скрытое поле, оба режима row scope).
- Прогон реального сценария через запущенный стек (`docker compose -f docker-compose.dev.yml`), health `/readyz`.
- Не помечай задачу выполненной без наблюдаемого результата. Тесты упали — скажи прямо, с выводом.

## 5. Запрещено

- SELECT * и любые DDL/DML к ClickHouse (только read-only SELECT).
- Секреты (пароль CH, ключи, токены, полные чувствительные строки) в логах, в коде, в аудите.
- `git push`, `rm -rf`, `docker compose down -v` (сброс данных) — без явного запроса пользователя.
- AutoMigrate-модель как замена доменной сущности: `domain/` остаётся чистым, GORM-модели живут в `repository/`.
- Новая библиотека веб-фреймворка/логгера/конфига/ORM вместо утверждённых (Fiber/zap/viper/GORM) — только через ADR и решение пользователя.

## Карта проекта (для ориентира; детали — через Graphify)

- `cmd/ehd-api` — entrypoint; `cmd/seed` — seed админа (GORM).
- `config` — viper. `pkg/{httpserver(Fiber),postgres(GORM),clickhouse,logger(zap)}`.
- `internal/app` — composition root: AutoMigrate, wiring, graceful shutdown.
- `internal/modules/{auth,reporter}` — `domain / repository / transport/http`; `auth/contract` — межмодульный интерфейс (без сети).
- ТЗ: `../.tz_extracted.txt`. Спеки: `specs/`. Конституция: `.specify/memory/constitution.md`.
