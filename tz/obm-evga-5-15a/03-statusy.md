# §7. Этап 3. Простановка статусов записи витрины

## Справочник статусов (`its_risk_status`)

Из 12 записей в обороте 8. Четыре (`in_work` id=3, `notification_received` id=5, `potential` id=10, `other` id=9) выведены из оборота — их `title` заменён на «-» (доработка справочника: EVGA-DB-002).

| id | code | Наименование | Кто проставляет |
|---|---|---|---|
| 1 | `high` | В работе у ДВГА | Система (стартовый) |
| 4 | `notification_sent` | Уведомление направлено | Система (автоматически) |
| 6 | `waiting_documents` | Ожидание документов (от ГУ) | Аудитор |
| 11 | `confirmed` | Подтверждено | Аудитор |
| 2 | `no_violations` | Не подтверждено | Аудитор |
| 7 | `partial_refund` | Подлежит возмещению | Аудитор |
| 8 | `full_refund` | Возмещено | Аудитор |
| 12 | `audit` | Аудит | Аудитор |

- **EVGA-BR-010.** В коде работать **по `id`**, не по `code`: семантика кодов разошлась с наименованиями (`high` = «В работе у ДВГА», `partial_refund` = «Подлежит возмещению»).
- **EVGA-BR-011.** Выпадающий список статусов фильтруется по `in$trash is null`, а не по `title = '-'`.

## Матрица переходов

- **EVGA-FR-020.** Разрешённые переходы:

| Из статуса | Разрешённые переходы | Условия |
|---|---|---|
| 1 «В работе у ДВГА» | → 4 (только автоматически при регистрации исходящего); → 2 | В 2 без уведомления — для заведомо ложных срабатываний; обязателен `risk_status_note` |
| 4 «Уведомление направлено» | → 6, → 11, → 2 | По результатам ответа объекта контроля |
| 6 «Ожидание документов» | → 11, → 2 | |
| 11 «Подтверждено» | → 7, → 12 | |
| 7 «Подлежит возмещению» | → 8, → 12 | Обязателен `amount_for_vozvrat`, значение ≤ `amount_part` |
| 12 «Аудит» | → 8 | ~~Обязателен `its_activity_id`~~ **07.09.2026 (ответ аналитика А2): при переводе в «Аудит» обязательных полей нет, мероприятие указывается опционально** |
| 2 «Не подтверждено» | терминальный | |
| 8 «Возмещено» | терминальный | Обязателен `refund`; если `refund < amount_for_vozvrat` — переход отклоняется, запись остаётся в 7 |

- **EVGA-BR-012.** Статус 4 вручную не выставляется и не снимается — только системой при регистрации исходящего.
- **EVGA-BR-013.** Из статусов 4 и 6 возврат в 1 невозможен: запись уже в отправленном документе.
- **EVGA-BR-014.** Любой переход вне матрицы блокируется с сообщением «Переход из статуса X в статус Y не предусмотрен».
- **EVGA-BR-015.** Каждое изменение статуса пишется в журнал `its_tb_5_15a_status_log` (EVGA-DB-003), включая автоматические.

## Массовая простановка

- **EVGA-FR-021.** Аудитор отмечает записи чекбоксами, выбирает статус и комментарий — применяются ко всем отмеченным.
- **EVGA-FR-022.** Массовая операция допустима только в пределах своего департамента.
- **EVGA-FR-023.** Записи с недопустимым переходом не обрабатываются. По завершении отчёт: «Обработано N, отклонено M» с перечнем отклонённых и причинами.
- **EVGA-FR-024.** Операция выполняется в одной транзакции.
