# §9. Этап 5. Формирование PDF

Файл формируется автоматически, состав и вёрстка — строго по утверждённому образцу.

## Структура файла

- **EVGA-FR-040.** Порядок: 1) уведомление на казахском; 2) приложение на казахском; 3) уведомление на русском; 4) приложение на русском.

## Постоянная часть (шаблон)

- **EVGA-FR-041.** Шапка: герб + двуязычное наименование «Қазақстан Республикасы Қаржы министрлігі Ішкі мемлекеттік аудит комитеті» / «Министерство финансов Республики Казахстан Комитет внутреннего государственного аудита». Фоновый водяной знак.
- **EVGA-FR-042.** Текст письма (рус.): «Онлайн бюджетным мониторингом идентифицированы **высокие риски** в расходной части бюджета по случаям, указанным в приложении к настоящему уведомлению. На момент уведомления наблюдаются **признаки неправомерного перечисления** на карт-счета физических лиц. С целью пресечения необоснованного использования бюджетных средств **рекомендуется самостоятельное устранение рисков** в срок не позднее 10 (десяти) рабочих дней. В противном случае будет рассмотрен вопрос о принятии **директивных мер реагирования.**» Казахская версия — по образцу. Текст редактируется только администратором.
- **EVGA-FR-043.** Подвал:

```
ДВГА по <область> КВГА МФ РК,
Подписано: <должность подписанта> <ФИО подписанта>

Исп. <ФИО аудитора>, тел <телефон>, эл.адрес <email>
Уведомление №:<номер> от <дата>
```

## Переменная часть

- **EVGA-FR-044.** Источники: адресат — `its_risk_notice_recepient` → `its_cli`; № и дата — шапка уведомления; департамент — `its_departments`; ФИО/должность подписанта — строка маршрута «Согласование» (фактический подписант); ФИО/телефон/email исполнителя — профиль аудитора (`users`).
- **EVGA-FR-045.** Таблица приложения (порядок и наименования — по образцу), источник `its_risk_notice_5_15a`: № п/п; Код ГУ отправителя (`gu`); Номер платежа (`ppo_pp`); Дата платежа (`paymentdate`, ДД.ММ.ГГГГ); Фамилия/Имя/Отчество (`fm`/`nm`/`ft`); ИИН (`iin`); Карт-счёт (`la1`); Сумма (`amount_part`, два знака после запятой).
- **EVGA-FR-046.** Колонки «Риск» и «Профиль риска» в печатную форму **не выводятся** — профиль используется только внутри системы.

## Правила генерации

- **EVGA-FR-047.** Проект PDF формируется при создании уведомления и перегенерируется при каждом изменении состава строк.
- **EVGA-FR-048.** Финальный файл формируется после подписания (до этого подписант может смениться — подвал изменится). После регистрации исходящего файл фиксируется как неизменяемый.
- **EVGA-FR-049.** Файл сохраняется в `files` (S3), связь через `its_risk_notice.file_pdf`.
