# План разработки модуля ОБМ ЕВГА (5-15а) в ehd2

Дата: 03.09.2026. Статус: черновик, к согласованию.

## Архитектурное решение

Новый модуль в существующем модульном монолите, по образцу reporter:

- **Бэкенд:** `back/internal/modules/evga/` — `domain / application / repository / transport/http`,
  регистрация в composition root `back/internal/app/app.go` (`/api/v1/evga`), RBAC через
  `auth/contract` (как `reporter/transport/http/guard.go`).
- **Данные:** модуль работает с **внешней** PostgreSQL `obm_evga@10.58.57.39` — это НЕ ehd-БД.
  Отдельное подключение `pkg/postgres.New(cfg.EVGA.DSN)`; **никакого AutoMigrate** на эту базу —
  DDL (EVGA-DB-001…005) только согласованными SQL-скриптами.
- **Режим чтения на старте:** отдельный DSN c параметром `default_transaction_read_only=on`
  (+ запросить у заказчика РО-пользователя на стороне БД). Пишущий DSN появится в фазе 3.
- **Конфиг:** `EVGA_PG_DSN` в `back/config/config.go` + `docker-compose.dev.yml`.
  Сделать модуль отключаемым (`EVGA_ENABLED`), чтобы стек поднимался без доступа к внешней БД.
- **Фронтенд:** новый Nuxt-слой `front/layers/evga/` (по образцу `front/layers/reporter/`):
  страницы реестра, карточки записи, карточки уведомления.
- **Excel-выгрузка:** переиспользовать паттерн `back/internal/modules/reporter/export/xlsx.go`.
- **ЭЦП:** переиспользовать `back/internal/modules/auth/eds/` (stub/ncalayer/ncanode) — после OQ-05.

## Процесс

Разработка — по SDD-харнессу: из `back/` и `front/` через `/specify → /clarify → /plan → /tasks →
/analyze → /implement`; спеки `back/specs/007-evga-*` и далее, трассировка на `EVGA-FR/BR/DB`
из `tz/obm-evga-5-15a/`. Для локальной разработки без доступа к боевой БД — поднять схему-реплику
`obm_evga` в dev-Postgres (compose) из DDL, полученного в фазе 0, и сид тестовых данных.
