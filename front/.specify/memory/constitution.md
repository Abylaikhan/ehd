# Конституция фронтенда ЕХД

Неизменяемые принципы, которым обязаны соответствовать все `spec.md`, `plan.md`, `tasks.md` и код. Изменение — только через `/constitution` с обоснованием и версией.

Версия: 1.0.0 · Действует с: 2026-08-20

---

## Принцип 1. Nuxt Layers как архитектура

- Приложение — единый Nuxt 4 SSR, декомпозиция по доменным layers (`base`, `auth`, `reporter`), зеркалящим модули бэкенда.
- Общий фундамент (design system, shell, `useApi`) — в `base`; доменные страницы/компоненты — в своём layer.
- Замена архитектуры (например, FSD) — только через ADR и решение владельца.

## Принцип 2. PrimeVue — единственная UI-библиотека

- Все элементы — PrimeVue 4. Другая UI-библиотека запрещена.
- Внешний вид — через дизайн-токены (кастомный navy-preset `app/theme.ts` + `var(--ehd-*)`). Точечные inline-стили запрещены (ТЗ).
- Общие компоненты ЕХД (AppShell, PageHeader, StatusTile, ServerDataTable, FilterBuilder, EmptyState, ErrorState, PermissionGate, UnsavedChangesGuard) переиспользуются, не дублируются.

## Принцип 3. Серверное состояние и Pinia

- Серверные данные — через `useAsyncData`/`$fetch` и типизированный клиент из OpenAPI (`shared/api`).
- Pinia — только для кросс-страничного состояния: сессия, навигация, справочники, несохранённый draft. Дублировать сервер-стейт в сторе запрещено.

## Принцип 4. Безопасность — на бэкенде, фронт не расширяет права

- Capability flags и доступные действия приходят из API; backend повторно авторизует каждую операцию.
- Скрытие маршрута/кнопки/колонки — не механизм безопасности. Фронт не может включить запрещённую колонку/фильтр/экспорт.
- При PATCH передаётся revision; ответ 409 `CONFIG_CONFLICT` → диалог перезагрузки, тихая перезапись запрещена.

## Принцип 5. Контракт с API

- Типы генерируются из `../back/openapi/` (OpenAPI 3.1) в `shared/api`; поля ответов не выдумываются.
- Состояние таблиц (поиск, фильтры, сортировка, курсор, размер страницы) отражается в query string.
- Даты в API — ISO 8601 UTC; локализованное отображение на клиенте.

## Принцип 6. UX и доступность (ТЗ, раздел 7)

- Desktop-only MVP, проектирование от 1280px, работоспособность от 1024px; проверка на 1024/1280/1440.
- Обязательные состояния экрана: Loading, Empty, Error, Access denied, Source unavailable; для форм — Validation, Dirty (UnsavedChangesGuard), Conflict.
- Доступность: контраст, видимый focus, клавиатура, подписи полей, aria-label для icon-only, смысл не только цветом (статус = иконка + подпись).
- Язык MVP — русский; `name_kk` хранится, но казахская локализация UI вне MVP.

## Принцип 7. Тестирование — гейт готовности

- Vitest + @nuxt/test-utils: преобразование query-state, form validation, permission-состояния.
- E2E — основной сценарий экрана. Нет hardcoded ролей/колонок; capability из API.
- `pnpm typecheck` без ошибок TypeScript; отсутствие console errors и дублирования токенов/стилей вне темы.

## Definition of Done (frontend)

1. Реализованы Loading/Empty/Error/Access denied/Success; для формы — Validation/Dirty/Conflict.
2. `pnpm build` и `pnpm typecheck` — чисто; lint без ошибок; тесты зелёные.
3. Экран проверен клавиатурой и на 1024/1280/1440 в поддерживаемых браузерах.
4. Нет inline-стилей вне токенов; PrimeVue — единственная UI-библиотека; capability/metadata из API.
5. Каждая задача трассируется к `REP-FR/BR`/Приложению D; Graphify-граф обновлён.
