# Спецификация (UI): ОБМ ЕВГА — подсветка сроков и фильтр «Подтверждено без решения»

- **ID**: 009-evga-deadlines-ui
- **Статус**: draft
- **Бэкенд**: back/specs/013-evga-deadlines (EVGA-FR-080/082)
- **Дата**: 2026-09-09

## 1. Контекст

Бэкенд отдаёт по каждой записи реестра `exec_due` (строка `YYYY-MM-DD` или пусто) и
`deadline_state` (`""`|`expiring`|`expired`), а также принимает query-фильтр
`confirmed_no_decision=true`. UI визуализирует срок и даёт быстрый фильтр.

## 2. Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | В гриде реестра строки с `deadline_state="expired"` подсвечены как просроченные (красный акцент), `"expiring"` — как истекающие (янтарный/предупреждение). Пустое состояние — без подсветки. |
| FR-2 | Колонка «Срок» показывает `exec_due` в формате ДД.ММ.ГГГГ с бейджем состояния (istёк/истекает); пусто — «—». |
| FR-3 | Быстрый фильтр «Подтверждено без решения» (чекбокс/переключатель в панели фильтров) — при включении добавляет `confirmed_no_decision=true` к запросу списка и экспорта; сбрасывается вместе с прочими фильтрами. |
| FR-4 | Подсветка — визуальная подсказка, не влияет на серверную пагинацию/итог; состояние приходит с сервера, клиент не пересчитывает даты. |
| FR-5 | Типы `EvgaRecord`/`EvgaFilters` дополнены полями `exec_due`/`deadline_state`/`confirmed_no_decision`; юниты утилит (если затрагиваются) зелёные, vitest проходит. |

## 3. Приёмка

1. Запись с истёкшим сроком видна красной строкой с бейджем «истёк» и датой.
2. Запись с истекающим сроком — янтарной с бейджем «истекает».
3. Включение «Подтверждено без решения» оставляет в списке только статус 11; выключение возвращает полный список.
4. SSR-рендер страницы реестра проходит; `pnpm test` зелёный.

## 4. Вне объёма

Подсветка в карточке (FR-080 про реестр); клиентский пересчёт сроков; экспорт колонки срока
(бэкенд экспорт не меняли).
