# Спецификация: Reporter UI — Админ-конструктор витрин

- **ID**: 004-reporter-admin-views
- **Статус**: implemented
- **Требования ТЗ**: REP-FR-020..044 (создание Data View, настройка колонок, публикация); Приложение D (`/reporter/admin/views`, `/reporter/admin/views/create`, `/reporter/admin/views/{id}`)
- **UX-эталон**: легаси-экран `ext_db_entities` (форма сущности: подключение+БД+таблица сверху, редактор «Атрибутов внешней БД» = колонки, `view_limits` = RLS по ролям)
- **Дата**: 2026-08-24

## 1. Цель и ценность
Дать администратору **визуально собрать витрину для отчёта** (мышкой, без API): выбрать источник → базу → таблицу, настроить колонки (видимость, подпись, тип, порядок, флаги), задать роли и ограничение строк, посмотреть предпросмотр и опубликовать. Кладётся на готовый backend (slices 003–006); повторяет структуру легаси `ext_db_entities`, но безопасно (physical_object, whitelist, RLS по профилю).

## 2. Пользовательские сценарии (администратор)
- Открывает `/reporter/admin/views` → список витрин (ID, подключение, таблица, БД, статус, дата), действия: открыть/опубликовать/отключить/удалить, кнопка «Создать».
- «Создать» → выбирает **источник → базу → таблицу** (последовательные списки из интроспекции), задаёт название/slug/описание → создаётся черновик с авто-подгруженными колонками → переход в карточку.
- В карточке настраивает **колонки** (таблица-редактор: код/тип — только чтение; подпись, тип отображения, порядок, видимость, поиск/фильтр/сортировка/экспорт).
- Задаёт **права** (роли) и **ограничение строк** (режим + колонки региона/подразделения) и параметры (пагинация, лимит экспорта, keyset-ключ).
- Жмёт **Предпросмотр** → видит первые строки текущей конфигурации (как увидит пользователь, без RLS — админ).
- **Публикует**; при незаполненных требованиях — понятная ошибка (нет видимых колонок/ролей). Может **отключить**/удалить черновик.

## 3. Функциональные требования
| ID | Требование (поведение) | Источник |
|---|---|---|
| FR-1 | Список витрин `GET /reporter/admin/views` с статусом и действиями; Empty/Error | REP-FR (список представлений) |
| FR-2 | Создание: выбор источника (`GET .../sources`), базы (`.../databases`), таблицы (`.../databases/{db}/tables`) — последовательно; `POST .../views` создаёт черновик | «Создание Data View» |
| FR-3 | Карточка витрины `GET .../views/{id}`: мета, параметры, колонки, роли | REP-FR |
| FR-4 | Редактор колонок (как «Атрибуты внешней БД»): source_name/source_type — read-only; label, display_type, position, visible, searchable, filterable, sortable, exportable — редактируемы; `PUT .../columns` | «Настройка колонок» |
| FR-5 | Права: выбор ролей (`GET /auth/admin/roles`) → `PUT .../permissions` | «Права» |
| FR-6 | Row scope (аналог `view_limits`): режим by_profile/unrestricted + колонки региона/подразделения + keyset-ключ + пагинация → `PATCH .../views/{id}` | «Ограничение строк» |
| FR-7 | Предпросмотр: `POST .../views/{id}/preview` → таблица первых строк | REP-FR-040 |
| FR-8 | Публикация `POST .../publish`; отключение `.../disable`; удаление `DELETE`; статусы отражаются | REP-FR-041..044 |
| FR-9 | Ошибки публикации (нет видимых колонок/ролей/slug) показываются понятно (`PUBLISH_VALIDATION`) | REP-FR-041 |
| FR-10 | Все экраны — только администратору (`middleware: ['auth','admin']`); backend авторизует повторно | Принцип 4 |
| FR-11 | Правки колонок/прав/параметров опубликованной витрины переводят её в draft (сервер); UI отражает статус | REP-FR-043 |

## 4. UX-контракт (по эталону `ext_db_entities`)
- **Список**: PrimeVue `DataTable` (ID, подключение/БД, код таблицы, статус-`Tag`, дата, меню действий), тулбар с «Создать».
- **Создание**: диалог/страница с каскадом Select: Источник → База → Таблица + поля Название/Slug/Описание.
- **Карточка**: секции сверху вниз — «Источник» (read-only подключение/БД/таблица, статус), «Колонки» (таблица-редактор с чекбоксами и inline-полями), «Права» (MultiSelect ролей), «Ограничение строк и параметры» (Select'ы), «Предпросмотр», действия (Сохранить колонки / Сохранить права / Сохранить параметры / Предпросмотр / Опубликовать / Отключить / Удалить).
- Русский UI; desktop 1024/1280/1440; состояния Loading/Empty/Error; тосты/`Message` на ошибки действий; иконки+подписи статусов.

## 5. Данные и контракт API
Новые admin-типы в `shared/api/types.ts` (зеркало backend 003–005): `DataSourceSummary`, `IntrospectDatabase/Table/Column`, `ViewSummary`, `ViewDetail` (мета+параметры+`columns[]`+`role_codes[]`), payload'ы create/updateMeta/columns/permissions. Поля — строго из backend.

## 6. Нефункциональные ограничения
- Только PrimeVue + дизайн-токены; переиспользуем `EmptyState/ErrorState`.
- Серверное состояние — `useAsyncData`/`useApi`; черновик правок колонок держим в локальном reactive до «Сохранить» (draft-состояние — допустимо в Pinia/локально по Принципу 3).
- Права/возможные действия — из API; фронт не расширяет (например, не публикует без данных — сервер всё равно отклонит).
- SSR-совместимость списка и карточки (`useAsyncData`).

## 7. Критерии приёмки
- **AC-1**: `/reporter/admin/views` показывает существующую `demo-transactions` со статусом; не-админа middleware уводит.
- **AC-2**: создание новой витрины через каскад Источник→База→Таблица создаёт черновик с авто-колонками и открывает карточку.
- **AC-3**: в редакторе колонок можно включить видимость/флаги и подпись; «Сохранить колонки» → `PUT` успешен; перезагрузка сохраняет.
- **AC-4**: выбор ролей и сохранение прав; выбор row-scope режима и колонок; сохранение параметров.
- **AC-5**: «Предпросмотр» показывает строки; публикация без видимых/ролей → понятная ошибка; с ними → статус `published`.
- **AC-6**: `pnpm build` без ошибок; unit-тест утилиты (маппинг колонок в payload) зелёный.

## 8. Вне объёма
- **Меню Reporter** (аналог `angular_menu`: размещение витрин в навигации, роли, вложенность) — отдельный слайс (нужен backend-модуль меню).
- **Управление источником** (форма создания/теста источника `/reporter/admin/sources`) — отдельный слайс; здесь источник только выбирается из существующих.
- `managed_query` (SQL/JOIN, легаси `ext_db_queries`) — Phase 2, вне MVP.
- Drag-and-drop переупорядочивание колонок (пока — числовое поле «порядок»); мультиязычные подписи (kk); revision/If-Match конфликты (добавим при мультиредакторе).
