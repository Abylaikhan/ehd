# Спецификация: ОБМ ЕВГА — UI согласования (маршрут, отправка, решения)

- **ID**: 008-evga-approval-ui
- **Статус**: implemented
- **Требования ТЗ**: EVGA-FR-050…057, 060…064 (АТ-09/09а/12/13);
  backend-контракт — `../back/specs/010-evga-approval/spec.md`
- **Дата**: 2026-09-08

## 1. Сценарии

- В карточке уведомления `/evga/notices/{id}` появляется блок **«Маршрут»**:
  - редактор шаблона (только статусы «Проект создан»/«Отправлен на доработку», `canWrite`):
    согласующие — упорядоченный список (добавление через автодополнение по
    `GET /notices/:id/participants`, удаление, порядок «вверх/вниз»); ответственный за
    «Создать исходящее» — автодополнение, предзаполнен инициатором (AT-09а);
    кнопка «Сохранить маршрут»;
  - кнопка **«Отправить на согласование»** — активна при заполненном маршруте
    (клиентская проверка + серверная 422 `ROUTE_INCOMPLETE` показывается текстом, AT-09);
    успех → показывается присвоенный номер, карточка обновляется;
  - при статусе «На согласовании» — кнопки **«Согласовать и подписать»** (подтверждение)
    и **«Вернуть на доработку»** (диалог с обязательным комментарием); сервер отвечает 403,
    если пользователь не исполнитель текущего этапа — показываем сообщение;
  - блок **«Ход исполнения»**: раунды, этапы, исполнители, результат, комментарий, даты.
- Шапка карточки показывает актуальные номер и статус после каждого действия.

## 2. Логика клиента

`layers/evga/utils/routeForm.ts`: `routeComplete(approverIds, outgoingId)` — для активности
кнопки отправки (сервер валидирует повторно). Vitest.

## 3. Вне объёма
