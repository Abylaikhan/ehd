# Спецификация: Auth UI

- **ID**: 001-auth-ui
- **Статус**: implemented
- **Требования ТЗ**: REP-FR-001/002, раздел 7 (интерфейсы), маршруты frontend, Приложение D
- **Дата**: 2026-08-21
- **API**: `back/openapi/openapi.yaml` (Auth Module, 14 путей `/auth`)

## 1. Цель
Пользовательские и административные экраны аутентификации ЕХД поверх Auth Module: вход (логин/пароль и ЭЦП), регистрация, смена временного пароля, сессия и guard'ы маршрутов, административное управление пользователями/ролями.

## 2. Маршруты и роли
| Маршрут | Роль | Назначение |
|---|---|---|
| `/login` | гость | Вход по логину/паролю и ЭЦП |
| `/register` | гость | Самостоятельная регистрация (pending) |
| `/change-password` | пользователь | Обязательная смена временного пароля |
| `/reporter/admin/users` | администратор | Реестр пользователей, проверка ИИН, роли/регионы/подразделения, разблокировка, временный пароль |
| `/reporter/admin/roles` | администратор | Список и создание пользовательских ролей |

## 3. Функциональные требования
| ID | Требование | Источник |
|---|---|---|
| FR-1 | Вход по логину/паролю → сессия; ошибки показываются inline/toast | REP-FR-001 |
| FR-2 | `password_change_required` → редирект на смену пароля | «Регистрация…» |
| FR-3 | Вход по ЭЦП (challenge→verify); в sandbox — dev-диалог подписи | REP-FR-001 |
| FR-4 | Регистрация → сообщение о статусе pending | REP-FR-001 |
| FR-5 | Сессия/роли берутся из `GET /auth/me`; хранится в Pinia (кросс-страничное) | REP-FR-002 |
| FR-6 | Guard'ы: неаутентифицированный → `/login`; не-админ на admin → 403/редирект | Безопасность |
| FR-7 | Реестр пользователей: серверная пагинация, поиск, фильтр по статусу | Реестр |
| FR-8 | Карточка пользователя: проверка ИИН, назначение ролей/регионов/подразделений (PATCH), разблокировка, временный пароль | REP-FR-010 |
| FR-9 | Создание пользовательской роли | REP-FR-011 |
| FR-10 | Выход (logout) очищает сессию | — |

## 4. UX и состояния
- Формы: валидация полей (inline), ошибка раздела (Message), submit-блокировка, toast результата.
- Списки: Loading (Skeleton), Empty, Error, Access denied.
- PrimeVue-компоненты, дизайн-токены `--ehd-*`, без inline-стилей. Desktop 1024/1280/1440.

## 5. Данные
Типы из `shared/api` (зеркало OpenAPI): `Me`, `LoginResponse`, `UserView`, `Role`, `Reference`, запросы. Права: `is_admin`/`roles` из API; фронт не расширяет права (backend авторизует повторно).

## 6. Критерии приёмки
- AC-1: неверный вход → сообщение; верный → редирект в приложение; `password_change_required` → `/change-password`.
- AC-2: `/reporter/admin/*` под не-админом недоступно; под админом — реестр с данными из API.
- AC-3: админ назначает роль/регион/подразделение → у пользователя в `/me` они появляются.
- AC-4: разблокировка и временный пароль работают из карточки.
- AC-5: logout → `/login`, повторный заход в защищённый маршрут редиректит на вход.
- AC-6: `pnpm build` без ошибок; unit-тесты валидаторов зелёные; экран проверен на 1280.

## 7. Вне объёма
- Реальный NCALayer-мост ЭЦП (в sandbox — dev-ввод подписи; продакшн-мост — Phase 2).
- Экраны Reporter-витрин, меню-конструктор (отдельные спеки).
