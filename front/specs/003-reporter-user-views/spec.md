# Спецификация: Reporter UI — Каталог витрин и пользовательская таблица

- **ID**: 003-reporter-user-views
- **Статус**: implemented
- **Требования ТЗ**: REP-FR-050..055; раздел «Пользовательское представление»; раздел «Поиск, фильтрация, сортировка и пагинация»; раздел «Экспорт в Excel»; Приложение D (`/reporter`, `/reporter/{slug}`)
- **Дата**: 2026-08-24

## 1. Цель и ценность
Первый пользовательский экран Reporter поверх готового backend-конвейера (slices 003–006): каталог доступных витрин и **динамическая таблица** `/reporter/{slug}`, которая по метаданным опубликованного представления рендерит колонки, грузит данные серверной keyset-пагинацией, показывает точный `total_count`, поддерживает глобальный поиск и **экспорт в XLSX**. Замыкает вертикаль «источник → представление → query → таблица» визуально.

## 2. Пользовательские сценарии
- Пользователь открывает `/reporter` → видит список доступных ему опубликованных витрин (по ролям) → переходит в витрину.
- Пользователь открывает `/reporter/{slug}` → таблица строится по метаданным (заголовки = `label`, порядок и типы из API); первая страница данных и `total_count` грузятся параллельно.
- Пользователь вводит глобальный поиск → таблица перезагружается с первой страницы.
- Пользователь жмёт «Показать ещё» → подгружается следующая keyset-страница (без пропусков/дублей).
- Пользователь жмёт «Экспорт» → скачивается XLSX (имя из `Content-Disposition`), с тем же поиском и RLS.
- Состояния: Loading, Empty, Error, Access denied (403), Not found (404), Source unavailable (503) — у каждого своё понятное отображение.

## 3. Функциональные требования
| ID | Требование (поведение) | Источник ТЗ |
|---|---|---|
| FR-1 | `/reporter` — список опубликованных витрин пользователя (`GET /reporter/views`); пустой список → Empty | REP-FR-050 |
| FR-2 | `/reporter/{slug}` грузит метаданные (`GET /reporter/views/{slug}`) и строит колонки динамически (label, порядок, тип) | REP-FR-051, 052 |
| FR-3 | Данные и `total_count` — отдельными параллельными запросами (`POST .../query`, `POST .../count`) | REP-FR-051; total_count параллельно |
| FR-4 | Keyset-пагинация «Показать ещё» по `next_cursor`; размер страницы из метаданных (20–200, default 50) | «Пагинация» |
| FR-5 | Глобальный поиск отправляется в `search`; применяется только к searchable-колонкам (сервер решает) | «Поиск» |
| FR-6 | Экспорт `POST .../export` → скачивание XLSX; имя файла из `Content-Disposition` | «Экспорт», REP-FR |
| FR-7 | Отображаемые колонки/операции — только из API; фронт не добавляет скрытые колонки и не расширяет права | Принцип 4, REP-BR-007 |
| FR-8 | Форматирование значений по `display_type` (дата/дата-время локализуются; NULL — прочерк) | REP-FR-052 |
| FR-9 | Состояние таблицы (поиск, page_size) отражается в query string и восстанавливается | Принцип 5, REP-FR-055 |
| FR-10 | Обязательные состояния: Loading, Empty, Error, Access denied, Not found, Source unavailable | Принцип 6, REP-FR-054 |
| FR-11 | Страницы требуют активной сессии (middleware `auth`); без сессии → `/login` | REP-FR-002 |

## 4. UX-контракт
- Каталог: карточки/строки с названием и описанием витрины; клик → `/reporter/{slug}`.
- Таблица: PrimeVue `DataTable` с динамическими `Column`; тулбар (поиск слева, «Экспорт» справа); под таблицей — «Загружено X из N» и «Показать ещё».
- Русский интерфейс; desktop 1024/1280/1440; иконки+подписи для состояний (смысл не только цветом).
- Экспорт — только клиентское действие по кнопке; во время экспорта кнопка disabled + spinner; `EXPORT_BUSY`/`EXPORT_TOO_LARGE` → toast с понятным текстом.

## 5. Данные и контракт API
Новые типы в `shared/api/types.ts` (зеркало backend slices 005/006): `UserViewListItem`, `ViewMeta`, `ColumnMeta`, `QuerySpec`, `QueryResult`, `CountResult`. Поля — строго из ответов backend; не выдумываются.

## 6. Нефункциональные ограничения
- Серверное состояние — через `useAsyncData`/`useApi`; Pinia не дублирует данные таблицы.
- Только PrimeVue + дизайн-токены (`var(--ehd-*)`); без сторонних UI и inline-хардкода.
- Переиспользуемые компоненты состояний (`EmptyState`, `ErrorState`) выносятся в `base`.
- SSR-совместимость: метаданные и первая страница грузятся через `useAsyncData` (сериализуются в клиент).

## 7. Критерии приёмки
- **AC-1**: `/reporter` показывает витрины пользователя; у пользователя без доступных витрин — Empty; ошибка загрузки — Error.
- **AC-2**: `/reporter/{slug}` строит колонки по метаданным (заголовки = label), рендерит первую страницу и `total_count`.
- **AC-3**: «Показать ещё» подгружает следующую страницу по курсору; счётчик «Загружено X из N» растёт; кнопка исчезает при `next_cursor=""`.
- **AC-4**: поиск перезагружает таблицу с первой страницы; отражается в URL и восстанавливается после reload.
- **AC-5**: «Экспорт» скачивает XLSX с именем из заголовка; при `EXPORT_BUSY`/`EXPORT_TOO_LARGE` — toast.
- **AC-6**: 403 → Access denied; 404 → Not found; 503 → Source unavailable; без сессии → редирект на `/login`.
- **AC-7**: `pnpm build` без ошибок; unit-тест форматирования значений/парсинга имени файла зелёный.

## 8. Вне объёма
- Конструктор фильтров по колонкам (typed FilterBuilder), сортировка по произвольной колонке — следующий слайс (backend поддерживает whitelist-фильтры; UI-строитель — отдельно).
- Админ-конструктор (`/reporter/admin/*`: источник, мастер представления) — отдельные слайсы.
- Сохранение пресетов фильтров, мультиязычность UI (kk), тёмная тема.
- Виртуализация/бесконечный скролл (сейчас «Показать ещё»).
