# Спецификация: ОБМ ЕВГА — экран реестра рисков 5-15а (read-only)

- **ID**: 005-evga-registry-ui
- **Статус**: implemented
- **Требования ТЗ**: EVGA-FR-012…014, 017, 018 (частично — история статусов появится в фазе 3),
  EVGA-FR-010/011 (отображение scope) — `../tz/obm-evga-5-15a/02-reestr-riskov.md`;
  backend-контракт — `../back/specs/007-evga-registry/spec.md`
- **Дата**: 2026-09-06

## 1. Цель

Аудитор ДВГА / куратор КВГА работают с реестром витрины рисков в вебе: фильтры, серверная
пагинация, карточка записи, выгрузка Excel. Только чтение (фаза 1).

## 2. Сценарии и состояния

- Пользователь с ролью `evga_auditor`|`evga_curator`|админ видит раздел «ОБМ ЕВГА» в сайдбаре
  (видимость по `Me.roles`; capability подтверждает backend — фронт прав не расширяет).
- `/evga` — реестр: грид EVGA-FR-012 (№, профиль, ГУ, отправитель, № платежа, дата, ИИН, ФИО,
  карт-счёт, сумма, статус, комментарий, уведомление, исходящее), фильтры EVGA-FR-013,
  пагинация с `total`, сортировка (whitelist backend), кнопка «Экспорт».
- `/evga/{id}` — карточка записи: все поля + суммы возмещения, ГБД ФЛ, привязки.
- Состояния: loading / error (retry) / `EVGA_SOURCE_UNAVAILABLE` (отдельный текст) /
  `ACCESS_DENIED` / пусто / **unmapped** (`scope.unmapped=true`) — информационное сообщение
  «Пользователь не сопоставлен с департаментом ДВГА (ИИН не найден в ОБМ ЕВГА)».
- Куратор/админ: дополнительный фильтр «Департамент» (из `/references`); шапка scope
  показывает «Все департаменты»; аудитор видит название своего департамента.

## 3. Контракт API

`GET /api/v1/evga/registry|registry/:id|registry/export|references` — по backend-спеке 007.
Типы — `shared/api/types.ts` (EvgaRecord, EvgaCard, EvgaScope, EvgaReferences, EvgaRegistryResponse).

## 4. Вне объёма

Чекбоксы/массовые операции и смена статусов (фаза 3), формирование уведомлений (фаза 4),
казахская локаль.
