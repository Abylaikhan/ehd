# Спецификация: ОБМ ЕВГА — UI формирования уведомлений

- **ID**: 007-evga-notices-ui
- **Статус**: implemented
- **Требования ТЗ**: EVGA-FR-016, EVGA-FR-030…036, §11.4 (удаление проекта);
  backend-контракт — `../back/specs/009-evga-notices/spec.md`
- **Дата**: 2026-09-08

## 1. Сценарии

- В реестре `/evga` аудитор отмечает записи и жмёт **«Сформировать уведомление»** →
  переход на `/evga/notices/create` (выбранные id передаются через состояние приложения).
- Экран группировки (EVGA-FR-032): таблица групп «Код ГУ | Наименование | Кол-во записей |
  Общая сумма | Адресат | Исключить»; адресат ищется по `GET /cli?q=` (автодополнение,
  от 2 символов); любую группу можно исключить (EVGA-FR-035); отклонённые записи — отдельным
  блоком с причинами (EVGA-FR-030/036).
- Кнопка **«Создать»** неактивна, пока хотя бы у одной включённой группы не выбран адресат
  (EVGA-FR-034); после создания — сводка и переход к списку уведомлений.
- `/evga/notices` — список: номер («—» у проектов), статус, ГУ, адресат, строк, сумма,
  дата; фильтры по статусу и номеру; куратор/админ видят департамент.
- `/evga/notices/{id}` — карточка: шапка, текст уведомления, таблица строк снимка;
  кнопка «Удалить проект» (только статус «Проект создан», подтверждение), 422 → сообщение.
- Сайдбар: пункт «Уведомления» в разделе «ОБМ ЕВГА».
- Права: формирование/удаление видят аудитор и админ (`canWrite`); backend авторизует
  повторно; куратор — только списки/карточки.

## 2. Логика активности «Создать»

`layers/evga/utils/noticeForm.ts`: `canCreate(groups)` — все не исключённые группы имеют
адресата и остаётся ≥1 группа. Покрыто vitest.
