# Спецификация (фронт): ОБМ ЕВГА — карточка уведомления ближе к экрану платформы

- **ID**: 009-evga-outgoing-ui
- **Статус**: implemented (проход 1)
- **Контекст**: по варианту B (спека 014) наш модуль заменяет платформенный экран «Исходящая
  корреспонденция». Приближаем карточку `/evga/notices/:id` к его виду. Разбор экрана —
  `../tz/obm-evga-5-15a/voprosy-analitiku-4.md` Часть 7.
- **Дата**: 2026-09-11

## 1. Объём (2 прохода)

**Проход 1 (эта спека, реализован):**
- Прогресс-степпер по статусам: Создан → Подписание → Канцелярия → Выполнен.
- Разбивка содержимого на вкладки: Документ / Предпросмотр / Ход исполнения / Приложение.
- Блок «Реквизиты отправителя» + вложения (PDF).

**Проход 2 (позже, блокирован данными):**
- Блок «Регистрационные реквизиты» (вид документа/характер вопроса/индекс дела) — нужны коды НСИ
  `docKind`/`character` от заказчика.
- Вкладка «Информация о доставке» (извещения `state*`) — нужен ответ по П-4 (кто принимает).

## 2. Функциональные требования (проход 1)

| ID | Требование |
|---|---|
| FR-1 | Степпер из 4 шагов; текущий шаг вычисляется чистой функцией `currentNoticeStep(statusId, out)`: 3 (Выполнен) при заявке «Исполнен» (3) или зарегистрированном исходящем (`out.doc_num`); 2 (Канцелярия) при созданном исходящем без номера; 1 (Подписание) при статусах 2/5/12; иначе 0 (Создан). |
| FR-2 | Шаги окрашиваются: пройденные — зелёные, текущий — акцент, будущие — серые (как на платформе). |
| FR-3 | Вкладки (PrimeVue `Tabs`): «Документ» (реквизиты + отправитель/вложения + текст), «Предпросмотр» (скачать PDF), «Ход исполнения» (`EvgaRouteCard`), «Приложение (N)» (таблица записей). |
| FR-4 | Блок «Реквизиты отправителя»: отправитель (департамент), ГУ, вложение — ссылка на PDF (`Скачать`). |
| FR-5 | Действия в шапке без изменений: Скачать PDF, Отправить в ЕСЭДО, Удалить (для проекта), К списку. |
| FR-6 | Состояния экрана (loading/denied/notfound/source/error) сохраняются. Права: пишущие действия только `canWrite`. |
| FR-7 | Юнит `currentNoticeStep` (vitest): все ветки — проект, согласование, подписание, доработка, исходящее без номера, зарегистрировано, исполнен. |

## 3. Приёмка

1. Проект без исходящего → активен шаг «Создан»/«Подписание» по статусу; вкладки переключаются.
2. Исходящее создано без номера → активен «Канцелярия».
3. Зарегистрировано (`doc_num`) → «Выполнен» зелёный до конца.
4. Вкладка «Приложение» показывает таблицу; «Ход исполнения» — маршрут; «Предпросмотр» — скачивание.
5. vitest зелёный; SSR карточки 200; визуальная проверка 1024/1280/1440.

## 4. Вне объёма

Регистрационные реквизиты и вкладка «Доставка» (проход 2); отправка на email; печать.
